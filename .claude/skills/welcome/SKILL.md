# Welcome the researcher

Build the project context without asking the researcher to manage files.

## Interview

Ask at most seven questions. Ask one question at a time. Use plain language.

1. What is your research field?
2. What is your main research question in one sentence?
3. What stage is the project at?
4. What data do you have now?
5. What tools do you already use?
6. What language should replies use?
7. Should result explanations be short or detailed?

Skip a question when the answer is already clear. If the researcher is unsure, accept that answer and continue.

## Set up the project

After the interview:

1. Fill [PROJECT.md](../../../PROJECT.md) from the answers. Keep unknown items visibly marked “not set.”
2. Record reply language, result detail, and tools in [memory/preferences.md](../../../memory/preferences.md).
3. Add three to five project terms to [memory/glossary.md](../../../memory/glossary.md). Use the researcher’s meanings.
4. Offer to register the first hypothesis. Ask for confirmation before changing [hypotheses.md](../../../hypotheses.md).
5. Offer to move all content marked “example — your AI will replace this” to `archive/`. Move it only after one explicit confirmation. Preserve the example files and their links together.

End with this exact sentence:

> Whenever you want to test something, just tell me — I’ll run it as a proper experiment.
